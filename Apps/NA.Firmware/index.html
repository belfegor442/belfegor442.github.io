01 / OVERVIEW

Diagnostics before the OS.

NA.Firmware explores a structured pre-boot workflow: initialize diagnostic stages, report what has actually been checked, preserve useful error context and provide a clear route into diagnostics.

The page separates project intent from verified capability. A visual preview is illustrative; it is not proof that hardware has been tested or that the current build can boot on a physical machine.

01 / POST

Power-on reporting

Present startup stages, explicit pass/fail states and useful failure context rather than decorative activity alone.

02 / DIAGNOSTICS

Hardware validation

Organize checks by component and platform capability. Unsupported checks must be reported as unsupported, never silently passed.

03 / RECOVERY

Safe hand-off

Keep the existing Windows Boot Manager and motherboard setup reachable, with a recovery path planned before installation is considered ready.

03 / ENGINEERING

Explicit layers. Honest states.

The intended design favors a small, auditable pre-boot interface: phase-based initialization, explicit dependencies, structured errors and predictable control flow. Platform-specific functionality should remain isolated from generic diagnostic logic.

LAYER 01

Platform interface

Use firmware-provided services where available and detect capability limits instead of assuming every board exposes the same interfaces.

LAYER 02

Diagnostic core

Run checks with defined outcomes: pass, fail, skipped or unsupported. Keep errors actionable and avoid claiming a successful check that never ran.

LAYER 03

Operator interface

Compact monochrome-first text, readable status labels, keyboard navigation and logs designed for troubleshooting.

04 / COMPATIBILITY & SAFETY

No unverified install claims.

Pre-boot software operates in a sensitive part of the startup chain. Compatibility must be demonstrated on real hardware, and recovery must be tested before the installer can be described as safe for everyday use.

Reference hardwareMSI PRO B650-S WIFI · AMD Ryzen 5 7600X · 32 GB DDR5 · Windows 11 x64
UEFI / BIOSExisting motherboard firmware and Click BIOS 5 are not replaced by this project.
Boot entryIndependent UEFI entry and a reliable Windows hand-off are required before an internal-drive installation can be considered ready.
Secure BootCompatibility must be explicitly tested and documented; do not assume unsigned development builds will launch with Secure Boot enabled.
Current claimPhysical-device compatibility and installation safety are not confirmed by this webpage.

Safety boundary: do not flash the motherboard BIOS, change the default boot order, or install unverified EFI binaries as part of experimenting with this project. Keep Windows Boot Manager and a known recovery route available.

05 / ROADMAP

From build to verified boot.

Readiness is earned through repeatable tests, not visual polish. These are engineering gates, not claims that every item is already complete.

  1. GATE 01 / BUILDReproducible build, correct output paths, and automated checks passing.
  2. GATE 02 / TESTSDiagnostic logic, error paths, unsupported hardware cases and failure reporting validated.
  3. GATE 03 / BOOTTested on the intended physical PC with clear logs and no reliance on an emulator as a substitute for device validation.
  4. GATE 04 / RECOVERYIndependent boot entry, reliable Windows hand-off, uninstall path and recovery procedure verified.
  5. GATE 05 / RELEASEDocument supported configurations, Secure Boot limitations, known issues and a verified release artifact.
06 / SOURCE

Inspect the implementation.

The repository is the source of truth for implementation details. Check the current build scripts, tests, documented limitations and release artifacts before trying any binary.
