SECURITY
MATTERS.

A clear place for security expectations, responsible disclosure and project security information.

Responsible disclosure

If you discover a security issue affecting a Weird Stuff website, application or repository, report it privately before publishing technical details. Include the affected component, a concise description, reproduction steps where appropriate, and the potential impact.

What to report

  • Authentication or authorization weaknesses.
  • Unexpected exposure of private or sensitive information.
  • Remote code execution, injection or serious input-validation issues.
  • Security-relevant configuration or deployment mistakes.
  • Other vulnerabilities with a credible security impact.

What not to do

  • Do not access, modify or delete data that does not belong to you.
  • Do not disrupt availability or degrade services.
  • Do not use automated testing aggressively against production services.
  • Do not publish credentials, personal data or exploit details obtained during research.

Contact

Security reports can be sent to orimuri12yt@gmail.com. Do not include passwords, access tokens or unnecessary personal information.

Scope note

This page describes the project's disclosure expectations. It does not claim certifications, formal compliance frameworks, penetration-testing coverage or security guarantees that have not been publicly documented.
